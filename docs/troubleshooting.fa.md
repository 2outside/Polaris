## درباره نسخه‌های بدون امضا (macOS / Windows)

Polaris **امضای کد ندارد**:

- **macOS**: نخست برنامه را به پوشه «Applications» بکشید؛ پس از هر نصب یا جایگزینی دستی از یک DMG تازه‌دانلودشده، این دستور را اجرا کنید:
  `xattr -cr /Applications/Polaris.app`. اگر پیام تنها می‌گوید توسعه‌دهنده قابل تأیید نیست، می‌توانید به‌جای آن روی برنامه کلیک راست کنید ← «Open» ← و تأیید کنید.
  این دستور ویژگی‌های گسترده بسته برنامه را به‌صورت بازگشتی پاک می‌کند، پس تنها آن را روی نسخه‌ای از Polaris اجرا کنید که به آن اعتماد دارید؛ سازوکار به‌روزرسانی خودش پاک‌سازی xattr را انجام می‌دهد.
  درون DMG همین راهنمای نخستین اجرا به پنج زبان قرار دارد (`README First.txt`) — وقتی Gatekeeper جلوی کاربر را می‌گیرد، او نمی‌تواند وارد برنامه شود و شاید هرگز این فایل را ندیده باشد، پس آن راهنما تنها توضیحی است که در آن لحظه در دسترس دارد.
- **Windows**: در پیام SmartScreen «Windows protected your PC» گزینه «More info» ← «Run anyway» را بزنید. درخواست‌های UAC (نصب helper / TUN) طبق روال ظاهر می‌شوند و فقط یک تأیید اضافه‌اند.

امضای کد هزینه گواهی و نیز مدل اعتماد مبتنی بر مانیفست امضا را وارد می‌کند که با خط لوله به‌روزرسانی سفارشی فعلی (هماهنگی VBS / osascript / pkexec) در تضاد است؛ بنابراین آگاهانه انجام نمی‌شود (به توضیحات crate با نام `updater` مراجعه کنید).

## صفحه سفید / خرابی تصویر / کرش‌های پیاپی فرایند GPU

بیشتر در درایورهای اختصاصی NVIDIA، ماشین‌های مجازی (کارت گرافیک مجازی QEMU) و دسکتاپ راه دور (xrdp) دیده می‌شود — محیط‌هایی که شتاب‌دهی سخت‌افزاری درست ندارند. لایه ترکیب‌کننده webview فریمی تولید نمی‌کند، اما **خود هسته پروکسی تحت تأثیر نیست** و به کار و انتقال ترافیک ادامه می‌دهد.

**رابط کاربری هنوز کار می‌کند** (صفحه سفید یا خرابی تصویر گاه‌به‌گاه؛ با بازکردن دوباره پنجره می‌توان وارد شد) ← تنظیمات ← نمایش ← «سازگاری گرافیکی» ← «شتاب‌دهی سخت‌افزاری» را خاموش کنید ← Polaris را دوباره اجرا کنید. (این بخش در macOS نمایش داده نمی‌شود: WKWebView کلید پشتیبانی‌شده‌ای برای غیرفعال‌کردن GPU ندارد.)

**رابط کاربری اصلاً باز نمی‌شود** (از ابتدا کاملاً سفید و تنظیمات در دسترس نیست) ← هیچ‌کدام از دو راه زیر **به رابط کاربری نیاز ندارند**:

### ۱. ویرایش مستقیم config.json

Polaris را ببندید، در سطح بالای فایل پیکربندی مقدار `"hardwareAcceleration": false` را اضافه کنید و دوباره اجرا کنید:

| سکو | مسیر |
|---|---|
| Linux | `~/.config/com.polaris.app/polaris/config.json` |
| Windows | `%APPDATA%\com.polaris.app\polaris\config.json` |
| macOS | `~/Library/Application Support/com.polaris.app/polaris/config.json` |

</div>

```json
{
  "hardwareAcceleration": false
}
```

<div dir="rtl">

خواندن پیکربندی عمداً «تحمل خطا در اولویت» طراحی شده است: فایل خراب یا نوع نادرست فیلد همیشه به «به‌صورت پیش‌فرض روشن» بازمی‌گردد، بنابراین مقدار نادرست این کلید نمی‌تواند اجرای برنامه را خراب کند (به `src-tauri/src/graphics_compat.rs` مراجعه کنید — متن خام پیش از ساخت پنجره مستقیماً خوانده می‌شود و به موفقیت مونتاژ store وابسته نیست).

### ۲. متغیرهای محیطی سکو (آزمایش یک‌باره، بدون تغییر پیکربندی)

این متغیرها را خود WebKitGTK / WebView2 **به‌صورت بومی** می‌خوانند و نیازی به همکاری برنامه ندارند. Polaris نیز عمداً متغیرهای هم‌نامی را که خودتان تنظیم کرده‌اید بازنویسی نمی‌کند، پس آزمایش موقت هنگام عیب‌یابی توسط برنامه مختل نمی‌شود.

</div>

```bash
# Linux (WebKitGTK) — DMABUF اصلاح اصلی صفحه سفید در NVIDIA است، COMPOSITING کرش هنگام تغییر اندازه را پوشش می‌دهد
WEBKIT_DISABLE_DMABUF_RENDERER=1 WEBKIT_DISABLE_COMPOSITING_MODE=1 polaris
```

```powershell
# Windows (WebView2)
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--disable-gpu"; .\Polaris.exe
```

<div dir="rtl">

در macOS کلید معادلی وجود ندارد (WKWebView رابط برنامه‌نویسی عمومی ارائه نمی‌دهد و WebKit #26651 مدت‌هاست پیاده‌سازی نشده)، بنابراین `hardwareAcceleration` در macOS بی‌اثر است — برنامه صادقانه یک هشدار در گزارش ثبت می‌کند و ادعا نمی‌کند که اعمال شده است. اگر در macOS با صفحه سفید روبه‌رو شدید، لطفاً یک issue باز کنید و گزارش‌ها را از این مسیر پیوست کنید:
`~/Library/Application Support/com.polaris.app/polaris/logs/` (در Linux مسیر `~/.config/...` و در Windows مسیر `%APPDATA%\...` با همان نام پوشه `logs/`).

> هر دو کلید در واقع یک کلید هستند: `hardwareAcceleration` (با معنای مثبت، مقدار پیش‌فرض `true` یعنی روشن). هر تغییری تنها پس از **راه‌اندازی مجدد کامل برنامه** اعمال می‌شود — متغیرهای محیطی فقط در همان لحظه ساخت webview خوانده می‌شوند.
